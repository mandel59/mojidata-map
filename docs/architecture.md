# 技術選定

2026-09-24 決定。

| 候補 | 利点 | 今回の判断 |
| --- | --- | --- |
| C++ / WinUI | Windows のフォント API に直接アクセスできる | Web との共通化が難しく、Windows 専用実装が大きくなる |
| Tauri / Rust | 配布サイズを抑えられる | OS ごとの WebView の描画差と Rust/ネイティブビルド環境が増える |
| Electron + TypeScript + React | Windows/macOS/Linux で同じ Chromium、Web と UI・データ・テストを共有 | 採用。配布サイズは増えるが文字描画環境を揃えやすい |

## 構成

- `src/core`: Unicode の検索・属性・符号化。UI と OS に依存しない。
- `src`: React UI、Web Worker、ブラウザ向けフォント処理。
- `desktop`: Electron のプロセス境界とアプリ起動。renderer の Node 権限を無効化し、context isolation と sandbox を使う。
- `tools`: 再現可能な参照配布物の解析と Unicode データ生成。
- `public/data`: 版と入力ハッシュを固定した生成データ。通常ビルドはネットワークに依存しない。
- `tests`: Unicode の境界条件と実際のユーザー操作を検証。

検索・描画用 Unicode データはアプリに同梱する。漢字詳細など大きなデータは分割し、必要時に読み込む。Web 版にサーバー API、アカウント、外部送信は必要ない。

ブラウザではローカルフォント列挙の可否が環境と権限に依存するため、フォント名入力とファイル読み込みも提供する。フォント表示と詳細解析の能力差は UI と互換性表へ明記する。

## 文字表の更新範囲

コードポイントは整数、Unicode 属性は開始点でソートされた範囲配列で保持し、二分探索で参照する。文字表は表示する128件を切り出し、状態を持たないセルの表示枠を再利用する。各枠のコード・名前・イベント処理は表示内容と一緒に更新し、ページ境界のキーボード移動後は選択文字へフォーカスを移す。

編集欄・検索条件・ブロックナビゲーション・フォント画面はメモ化し、変更のない props を安定させる。閉じたブロック一覧の内容は生成せず、非表示フォント画面では選択文字の解析を更新しない。フォントを保持したまま、再表示時に現在の選択を反映する。解析用のCSSフォント名は `FontPanel` 内の state とし、共通の `font` / `composite` 設定を更新するコールバックを渡さない。ファイル読込・端末フォント選択・解除やその非同期完了が共有表示設定へ波及しない。ブロック別フォントの編集は表示設定内の `BlockFontSettings` が担当し、既存の保存形式を維持する。文字サイズのプレビューは従来どおり表示用 Context 内で更新する。

JSON は読込中の Promise と解決済みオブジェクトの参照をキャッシュする。文字詳細は解決済みデータを同期参照し、キャッシュ済みのページ移動で余分な state 更新を起こさない。未読込の Unihan / 東アジア文字 / 異体字データだけを非同期で取得し、古い選択に対する完了通知は破棄する。読込失敗は表示し、次の選択で再取得できる。

統計画面は初めて開くときに読み込み、以後は集計結果とDOMを保持して表示を切り替える。`memo` と安定した props によって、非表示中の文字移動・編集では再描画しない。集計単位と絞り込みも再表示まで保持する。

## 検索と画面の境界

文字マップの移動、文字検索、絵文字検索を分ける。マップ内検索は一致コードポイントを保持し、同じ条件の再実行では現在位置の次の一致へ循環移動する。文字検索とは状態を分け、`useSearchWorker` により1つの Worker とそのデータを共有する。Worker は検索実行時に遅延起動する。漢字は文字検索の条件カテゴリで、`CharacterQuery` が Unicode・Unihan・UAX #60 の条件を保持する。Worker は漢字条件がある場合だけ索引を読み、絞った候補コードポイントへ Unicode の属性・名前条件を適用する。クエリIDで古い応答を破棄し、画面を切り替えても条件・結果・選択・ページを保持する。

通常の名前検索では正式名の範囲表と別名から候補を作り、その候補へ従来と同じ属性・名前条件を適用する。アルゴリズム名の `*` はコードポイントの16進値に展開して照合する。制御文字の正式表示名となる別名は、別名検索をオフにしても候補に含める。私用・未割当・サロゲート・非文字の代替名が一致しうる場合は全件走査を維持し、範囲表にない文字を失わない。漢字等ですでに候補がある場合とコードポイント直接指定も従来経路を使う。

漢字索引はコードポイントと `kRSUnicode`、`kTotalStrokes`、`kAlternateTotalStrokes`、13項目の読み・意味と、出典・辞書・異体字・字種・数値の32属性を持つ。従来の先頭列を維持して読みの列を追加し、Worker は索引の `fields` メタデータで読み条件と列を対応付ける。読み条件は属性名から文字列への辞書で保持し、すべてを AND で照合する。生成器とUIは `src/core/unihanReadings.json` の項目定義を共有する。総画数は通常値と出典付き代替値のいずれかを照合し、部首番号・枝番・内画数は同じ要素内で照合する。枝番は未指定なら全形、空文字列なら枝番なしを意味する。詳細の Unihan 分割ファイルを検索時に読み込む必要はない。部首と枝番の有効な組み合わせは `CJKRadicals.txt` から生成した小さな辞書 `radicalForms` として基本データに同梱する。総画数の候補も両画数属性から生成した `hanTotalStrokes` として基本データへ同梱する。条件の選択肢を表示するために漢字索引を追加読込・展開しない。

追加条件は `src/core/propertySearch.json` でラベル・元属性・データ源・照合方法を共有し、`CharacterQuery.properties` に属性ごとの値を保持する。UAX #60 の4ファイルは Unihan と同じタブ区切りで読み、15属性・18,815文字の `east-asian-index.json` と文字詳細用 `east-asian/` 分割ファイルを生成する。版・ハッシュは既存の UCD アーカイブの固定値で検証する。Worker は必要な索引だけを読み、両方必要なら候補集合の積を取り、最後に Unicode 条件を適用する。文字詳細は索引全体ではなく manifest にある分割ファイルだけを読み、元の値を表示・コピー・JSON保存する。

漢字の異体字ボタンは既存の文字詳細用 Unihan 分割ファイルから作る。9種類の関係属性だけを解析し、出典注記と移動先を分離、自己参照・不正な値を除外、同じ移動先の関係を統合する。`CharacterDetails` は安定した `onLocate` 経由でマップへ移動し、検索の条件・結果は維持する。

絵文字一覧は64件の状態を持たない表示枠を再利用し、フィルター変更や最終ページでも名前・字形・選択・挿入ハンドラーをまとめて更新する。グループ候補と表示ページはメモ化し、ページキーの選択位置は表示中の64件だけから求める。`CharacterGridSurface` とセルCSSを文字一覧と共有し、文字サイズのプレビューは小さなCSSホストだけを更新する。絵文字画面は初回表示後のDOMと状態を保持するが、非表示中のページキーには反応しない。セルの選択色は即時更新し、共通ボタンの背景色アニメーションによる不要な再描画を防ぐ。

検索結果の共通部は `CharacterCollection`、複数コードポイントのプレビューは `SequenceDetails`。現在の絵文字検索のデータ源は `EmojiPanel` で、プレビューはコードポイント列・名前・属性一覧という形で受け取る。将来の資料も文字列全体の追加・コピーを維持して接続する。機能ごとの拡張先は [画面設計](ui-design.md) を参照。

## 検証・配布

Node.js 24 LTS と npm の lockfile を用いる。Vitest でデータ処理、Playwright でブラウザの操作を確認する。Windows 向け Electron パッケージ生成は CI でも実行可能にする。Linux から生成できることと、Windows 実機で動作することは区別して記録する。

参照: [Electron セキュリティ](https://www.electronjs.org/docs/latest/tutorial/security)、[Vite](https://vite.dev/guide/)、[electron-builder](https://www.electron.build/)。
