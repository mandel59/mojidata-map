# サンプル表の表示順と論理順

- 依頼: `office العربية 日本語` の解析表が概ね左からの順に見える一方、アラビア語後方の空白だけが前へ出る理由を調べ、順序ポリシーと切替を見直す。
- 原因: 文字体系区間は入力順、各区間内はfontkitの出力順という混合順序だった。アラビア語区間には直後のCommon文字である空白も含まれ、RTL区間全体の反転で空白が区間先頭へ移っていた。段落全体のUnicode双方向配置は表に適用していなかった。
- 表の既定を「表示順（左から）」とし、「論理順（入力順）」へ切り替える選択欄を追加した。
- 表示順は解析テキストを改行保持・折返しなしでブラウザに非表示配置し、各グリフの元文字範囲をRangeで測って段落を上から・各段落を左から並べる。ブラウザと同じ双方向処理を使うため、中立文字を文字体系区間と一緒に誤って反転しない。
- 論理順は元文字のUTF-16範囲で並べる。どちらもGlyph ID・position・元文字範囲の組を維持し、行からの文字選択を保つ。元文字範囲を特定できない行はfontkit出力順のまま末尾へ置く。
- 保存JSONは従来のfontkit出力配列とrun情報を維持し、選択中の`tableOrder.type`と表から元配列への`glyphIndices`を追加した。
- 日本語・英語の切替ラベルを追加した。
- 検証: 翻訳検査、TypeScript型検査、本番ビルドが成功。独自フィクスチャの`A ببب A`で、表示順が`2, 1, 9, 8, 7, 1, 2`、論理順が`2, 1, 7, 8, 9, 1, 2`となり、切替後も対応する元文字位置を選択できるE2Eを確認した。
