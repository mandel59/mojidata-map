## BabelMap の文字履歴機能の調査

- 依頼に応じ、Character History の役割を公式ヘルプと解析済み `var/babelmap-resources.json` で確認。今回は解説のための調査であり、アプリ実装・配布物は変更しない。
- [公式メニューの説明](https://www.babelstone.co.uk/Software/BabelMap_Menu.html)では、選択した文字について各 Unicode 版の基本属性を一覧にする機能として説明されている。Tools → Character History から開ける。
- [文字情報の公式ヘルプ](https://www.babelstone.co.uk/Software/BabelMap_Menu_Tools_Properties.html)では、F9 で開く Character Properties 内の Character History ボタンからも開けること、追加版の表示と属性履歴が別の情報であることを確認。
- [公式機能一覧](https://www.babelstone.co.uk/Software/BabelMap_Features.html)には Unicode 1.0.0 / 1.0.1 の対応付けも記載。初期版で別のコードポイントにあった文字は、現在のコードポイントだけを固定して比較すると履歴を取り違えるため、実装時には対応付けが必要。
- 手元の17ベータの PE リソースでは DIALOG/195 が Character History。一覧と Copy / Close ボタンを確認した。DIALOG/198・199 の Unicode Version History は各版全体のコードポイント内訳とその版のブロック一覧を扱う別画面。EXE の起動検証や履歴画面の全列の確認はしていない。
- 具体例として、U+200B ZERO WIDTH SPACE の一般カテゴリが Unicode 4.0.1 で Zs から Cf に変わったことを [Unicode の公式変更履歴](https://www.unicode.org/reports/tr44/tr44-4.html)で確認。このような属性変更は、現行値と Age だけでは再構成できない。
- Mojidata Map は現在版の属性と追加版を表示できるが、各過去版の属性履歴は未実装。実装候補は文字詳細から開く版別の表で、過去版の UCD と初期版のコードポイント対応を整備する必要がある。

## 漢字条件の統合、総画数と部首の枝番

- 依頼: 「部首・画数」「読み・意味」を「漢字 (Unihan)」へ統合し、複数の総画数に対応する検索を追加する。康熙部首の枝番を調べて指定方法を決める。
- Unicode 18 の [UAX #38 revision 41](https://www.unicode.org/reports/tr38/tr38-41.html) と同梱公式データを確認。`kTotalStrokes` は仕様上単一値で、索引の102,999文字すべてが1値（1〜84画）だった。別の数え方を持つ `kAlternateTotalStrokes` は104文字にあり、103文字は出典付き数値、井の1文字は `-`。卿は通常10画、代替値 `12:JK`。複数画数への対応にはこの別属性も必要だった。
- `kAlternateTotalStrokes` を検索索引の末尾へ追加し、通常の総画数と代替画数のいずれかが一致すれば採用する。出典記号や `-` は画数として扱わない。空白区切りの複数通常値・複数代替値にも対応し、一致が重複してもコードポイントを重複させない。内画数と部首の画数を足して総画数を推測しない。
- 総画数は正の整数を入力する条件。総画数だけでも Worker が漢字索引を読み込む。別の数え方を含むことを入力欄の説明で明示し、適用・更新・個別解除を既存チップと統一した。
- `kRSUnicode` の枝番なしは伝統形、`'` は中国の簡略形、`''` は中国以外の簡略形、`'''` は中国以外の別の簡略形。実データの部首画数要素数は順に99,582 / 3,792 / 81 / 6。要素数であり文字数ではない。
