# Nishiki-tekiのサンプルでVS付きグリフが通常字形になる問題

入力`⊕⊕︀⊗⊗︀⊜⊜︀`を実フォントで再現。修正前はVS付きの文字にも基本グリフ3335 / 3337 / 3342が返ったが、cmap format 14ではFE00付きに23076 / 23077 / 23078が登録されていた。

原因はfontkit 2.0.4のgetVariationSelector。セレクター検索の添字iをdefault UVSの検索で上書きし、その検索が不一致の場合にnon-default UVSの検索まで省略していた。default/non-default両方を持つセレクターに影響する。

既存の互換パッチに、セレクターレコードが存在すればnon-defaultテーブルを独立に検索する修正を追加。Node/ブラウザーのESM/CJS全4配布コードへ適用する。npm ci・dev・build時に適用し、再実行しても重複適用しない。Vite依存キャッシュは既存のパッチハッシュ方式により次回サーバー起動時に切り替わる。

既存VariationScopes.ttfでdefault/non-defaultが混在するFE00/E0100、未登録ペア、未登録セレクター、ソース範囲を回帰テストした。修正前は失敗、修正後は成功。単体テスト110件と関連E2E14件成功。実際のNishiki-tekiをブラウザーで読み込み、報告文字列の6グリフのIDとVS付き輪郭の差異を確認した。

## 本番反映

ユーザー指示によりCloudflareへデプロイした。公開バージョンは`8aa0c17d-3f7a-44ed-87a0-261f1673883f`。公開HTMLが今回のビルドと一致し、本番URLでNishiki-tekiの`⊕⊕︀⊗⊗︀⊜⊜︀`がGID `3335, 23076, 3337, 23077, 3342, 23078`になること、および各VS付き輪郭が通常字形と異なることを実ブラウザーで確認した。
