# 検索・閲覧の画面設計

2026-09-25。主対象は 1024×600〜1366×768 の小型ノートPC。操作する対象ごとに画面を分け、機能追加は画面内の条件カテゴリ・資料・操作へ収める。検索・選択・編集・コピーまで、ページ全体のスクロールを必要としない構成にする。

## トップレベルの分類

| タブ | 主な役割 | この画面の操作 |
| --- | --- | --- |
| 文字マップ | コードポイント順に閲覧する | 面、ブロック、全面のブロック一覧、コード指定、未割当表示、表示設定、マップ内の循環検索 |
| 文字検索 | 条件に一致するコードポイントを探す | 文字・名前の入力、条件カテゴリの縦タブ、条件チップ、検索結果 |
| 絵文字検索 | 単体の絵文字や絵文字列を探す | Emoji 18 の名前・グループ検索。選択・追加・コピーはシーケンス全体を扱う |
| フォント | フォントと字形を調べる | ファイル読込、ローカルフォント、収録範囲、輪郭、OpenType、プレビュー・PNG出力 |
| Unicode データ | 収録範囲とデータを調べる | ブロック・Script・Age・面の統計、絞り込み、TSV出力 |
| ブックマーク | 保存したコードポイントを再利用する | 選択、文字表で表示、一覧保存 |

タブはフラットに並べる。「文字検索」内に文字／絵文字タブや検索方法ドロップダウンを設けない。漢字検索は文字検索の条件カテゴリとして扱い、独立した画面にしない。

面・ブロック移動とコード指定は文字マップだけに表示する。ブロック一覧は全面のブロックを対象にし、ドロップダウンは選択中の面だけを対象にする。検索結果の「文字表で表示」は明示的な画面移動として扱う。

文字マップの検索欄は枠の内側の先頭に置き、文字検索と同じ段に検索欄・検索ボタン・表示設定を並べる。文字・名前・別名・コードポイントで検索すると、現在位置より後の一致文字へコードポイント順に移動する。末尾まで進むと先頭へ戻り、検索ボタンまたは Enter の繰り返しで一致文字を巡回する。検索欄に一致位置と件数を表示し、該当なし・空入力では選択を変えない。

文字マップと文字検索の入力・結果は独立して保持する。文字検索タブへ切り替えた場合は、条件・結果・ページ・選択を保持する。Ctrl+Shift+F（macOS は Cmd+Option+Shift+F）はどの画面からも文字検索の入力欄へ移動する。ダイアログ表示中・IME変換中には移動しない。修飾キーは完全一致で判定し、Ctrl/Cmd+F や macOS の Cmd+Shift+F など既定の操作を奪わない。

## 条件カテゴリと条件チップ

文字検索には、文字・名前の入力、追加済み条件、条件追加欄、結果一覧を置く。タブと重複する「文字検索」の見出しは置かず、検索欄・検索ボタン・表示設定を一段にまとめる。

| 基本条件 | 文字分類 | 一般カテゴリ、Script |
| 基本条件 | Unicode の範囲 | Block、面、Age |

| 基本条件 | 名前の照合 | 正式名だけで検索、単語全体で一致 |
| 漢字 (Unihan) | 部首・画数 | 康熙部首と枝番、内画数、総画数 |
| 漢字 (Unihan) | 中国語・意味 | 普通話・広東語、英語の意味、商務新字典、唐代音、反切 |

| 東アジア (UAX #60) | 小篆の字形 / 小篆の出典 | 対応する漢字・部首 / 4種類の文献番号 |

縦タブ一覧に「基本条件」「漢字 (Unihan)」「東アジア (UAX #60)」の見出しを置く。単一のタブ一覧として上下・Home・Endキーでグループをまたいで移動し、選択中のタブだけをTabキーの移動先にする。入力途中の値・適用済みチップをカテゴリ切替でも保持する。小画面では内部スクロールを使う。

`kRSUnicode` と `kTotalStrokes` の元の分類は IRG Sources だが、出典番号と一緒に長いフォームにせず「部首・画数」へ分割する。総画数は `kAlternateTotalStrokes` も含める。読みも言語で3タブへ分割する。追加した項目と照合方法は[選定記録](investigations/property-search-priorities.md)を参照。

値を選んで「追加」すると条件チップを作り、結果を更新する。カテゴリや Bidi クラスなど単一値の項目は1条件で、再追加は値の置き換えになる。二値属性は属性名ごとに追加でき、追加済みの属性は選択肢で無効にして重複を防ぐ。各属性を別のチップとして表示し、個別に解除できる。すべての条件は AND で組み合わせる。例えば `ASCII_Hex_Digit` と `Lowercase` を Basic Latin 内で組み合わせると `a`〜`f` に絞られる。

Unicode 条件・Unihan 条件・UAX #60 条件も同じ検索へ渡せる。例: `一般カテゴリ: Lo` ＋ `康熙部首: 水 / 85` ＋ `内画数: 0` ＋ `普通話: shui`。

チップには項目名と値を表示し、×で個別解除、「すべて解除」で初期条件へ戻す。表示されていない条件が残らないよう、読み・意味は項目名を各チップ内に、部首の形は部首のチップ内に含める。部首の解除では枝番の指定も解除する。チップを解除したときは次の操作対象へフォーカスを戻す。縦タブは上下・Home・Endキーでも選べる。

文字・名前の入力は検索ボタンで確定する。値を入力・選択しただけの追加欄と、検索へ適用したチップを区別する。OR条件・単一値の属性に対する複数値指定・正規表現は未対応。

## 漢字の画数と部首の形

総画数は内画数と同じ形式のドロップダウンで選択し、`kTotalStrokes` と `kAlternateTotalStrokes` の登録値のいずれかに一致させる。Unicode 18 の `kTotalStrokes` は単一値で、別の数え方は `kAlternateTotalStrokes` に `12:JK` のように格納される。例えば「卿」は10画でも12画でも一致する。複数の画数が同じ文字に一致しても結果は1文字だけ。`-` は別画数がないことを示す記号として扱い、画数として検索しない。候補は通常・代替の両属性から集めた画数を数値順に並べる。登録されていない国・地域の画数を推測しない。

康熙部首の番号は1〜214。「部首の形（枝番）」は番号に付随する指定として扱い、初期値は「すべての形」。選んだ番号について Unicode 18 の `CJKRadicals.txt` に定義された形だけを候補に表示する。部首未選択では枝番欄を無効にし、番号を変えて以前の枝番が使えなくなった場合は「すべての形」へ戻す。有効な枝番は維持する。形の区別は次のとおり。

| 枝番 | 選択欄の表示 | 例（部首212、内画数0） |
| --- | --- | --- |
| なし | 伝統形 | 龍 `212.0` |
| `'` | 簡略形1 | 龙 `212'.0` |
| `''` | 簡略形2 | 竜 `212''.0` |
| `'''` | 簡略形3 | 𱷥 `212'''.0` |

部首の形を選ぶだけでは検索へ反映せず、「追加／更新」で番号と一緒に適用し、チップで指定を確認する。チップは `康熙部首: 212'''` のように番号と枝番だけで表記し、枝番の説明は選択欄へ残す。「すべて」は `212（すべての形）`、明示した「枝番なし」は `212` と区別する。枝番の定義がない部首では「すべての形」の補足を省略し、例として部首85は常に `85` と表示する。選択欄では使用地域と混同しないよう「簡略形1」〜「簡略形3」と呼び、国名・地域名をラベルに含めない。部首・枝番・内画数は同じ `kRSUnicode` 要素で照合する。例えば「直」の `109.3 24.6` を、部首109＋内画数6には一致させない。総画数は独立した属性として AND で組み合わせ、康熙部首の画数と内画数の加算からは推測しない。

参照: Unicode 18 [UAX #38 の kRSUnicode](https://www.unicode.org/reports/tr38/tr38-41.html#kRSUnicode)、[kTotalStrokes](https://www.unicode.org/reports/tr38/tr38-41.html#kTotalStrokes)、[kAlternateTotalStrokes](https://www.unicode.org/reports/tr38/tr38-41.html#kAlternateTotalStrokes)。

## 項目別の読み・意味

[Unicode の Unihan 検索ページ](https://www.unicode.org/charts/unihansearch.html)の Readings にある13項目を「漢字 (Unihan)」グループの「中国語・意味」「日本語・韓国語」「その他の読み」内の独立した入力欄として表示する。種類を選ぶ共通ドロップダウンは使わない。言語や資料をまたいで複数の条件を AND で組み合わせ、項目ごとのチップで更新・個別解除できる。

| 入力欄 | Unihan 属性 |
| --- | --- |
| 英語の意味 | kDefinition |
| 広東語 (Jyutping) | kCantonese |
| 商務新字典の読み | kSMSZD2003Readings |
| 普通話 (Pinyin) | kMandarin |
| チワン語 | kZhuang |
| 唐代音 (Tang) | kTang |
| 反切 | kFanqie |
| 日本語（かな） | kJapanese |
| 日本語の音読み（ローマ字） | kJapaneseOn |
| 日本語の訓読み（ローマ字） | kJapaneseKun |
| 韓国語（ハングル） | kHangul |
| 韓国語 (Yale) | kKorean |
| ベトナム語 | kVietnamese |

普通話・広東語は従来どおり声調を無視して音節一致、チワン語は大文字・小文字を区別しない語単位の一致。残りの項目は NFC 正規化後の、大文字・小文字を区別しない部分一致とする。ベトナム語などの区別に必要な符号を削除しない。商務新字典は普通話・広東語の両方を含む資料の値として検索する。例: `日本語（かな）: みず` ＋ `普通話: shui` ＋ `韓国語（ハングル）: 수` で「水」が一致する。

Unicode の Unihan_Readings.txt 全属性ではなく、指定された検索ページの Readings 項目が対象。欄を増やしても結果・プレビュー・編集欄の位置を変えず、条件欄の内部でスクロールする。

## 結果とプレビュー

Page Up / Page Down は現在表示中の一覧を1ページ移動する。文字マップは128コードポイント単位で現在の面内、文字検索・ブックマークは128件単位、絵文字は64件単位。同じページ内位置の選択を維持し、短い最終ページでは末尾へ合わせる。グリッドから操作した場合は選択項目へフォーカスを戻す。未割当を隠す場合は同じコード位置以降の表示文字（なければページ内末尾）を選び、空ページもページ送りで抜けられる。最初・最後のページで循環しない。入力欄・選択欄・条件タブ・IME変換中・修飾キー付き・ダイアログやポップオーバー表示中ではページ送りを行わない。

文字・絵文字の一覧は矢印キー、Home / End、Enter、Tabの処理を共有する。上下は表示列数、左右は1件、Home / Endは行の先頭・末尾（短い最終行では実際の末尾）へ移動する。Tabで一覧を通る項目は選択中の1件だけとし、未選択なら先頭にする。Enterはシーケンスを分割せず全体を追加する。修飾キー・IME変換中のキーは処理しない。検索結果・絵文字・ブックマークの矢印移動は現在のページ内とし、文字マップのコードポイント単位でのページ境界移動は維持する。ページボタンは移動先の先頭を選択し、Page Up / Downはページ内位置を保つ。絵文字の検索条件変更時も先頭を選択し、0件なら選択を解除する。

絵文字一覧も文字マップと同じセル寸法・1pxの罫線を使い、一覧領域の幅600px未満では8列、それ以上では16列にする。1ページは64件。上部に検索欄・表示設定、その下に件数・グループ選択、下部にページ送り・Emoji版を配置し、セル一覧だけをスクロールする。名前は1行で省略し、全文はツールチップと選択後の詳細に表示する。標準の文字サイズ30pxでセルの高さは56.5px。文字サイズは共通の表示設定に従い、絵文字用フォントを使う。

文字検索は整数コードポイントの配列、絵文字検索はコードポイント配列を持つ項目を結果として保持する。検索条件をUI上でまとめることと、文字列を1文字ずつ分割することを混同しない。絵文字の ZWJ、肌色、国旗等は全体をバッファへ追加・コピーする。

広い画面では、文字マップ・文字検索・絵文字検索・ブックマークのプレビューを同じ右側に置く。大きな字形、名前、追加・コピー、属性という順番を揃える。絵文字検索の一覧内に別のプレビューを置かない。フォントの収録文字では同じ配置・開閉操作のグリフ情報パネルを使う。フォントのサンプル・情報タブとUnicodeデータには汎用の文字プレビューを表示しない。

文字詳細の「漢字の異体字・関連字」は、標準化異体字列・絵文字表示列と同じボタン形式で字形・コードポイント・関係の種類を表示する。対象は Unihan の簡体・繁体、日本の新旧字体、意味上／特定語義の異体字、同形・字形類似、互換漢字の統合先。自分自身を除き、同じ移動先は1つのボタンへまとめ、関係を併記する。出典注記はツールチップと元の Unihan データで確認できる。ボタンは文字マップへ移動し、編集バッファへは挿入しない。モバイルの文字情報ダイアログは移動時に閉じる。

幅700px以下では、プレビューを結果の下の選択表示にし、詳細はダイアログで開く。絵文字も同じ配置・操作を使う。編集バッファはすべてのタブで下端に保持する。

文字情報では「標準化異体字列・絵文字表示列」の次に「漢字異体字列（IVS）」の折りたたみ欄を置く。選択文字を基底文字とするIVD登録列だけをVS順で表示し、件数は一意なシーケンス数とする。各項目は字形、基底文字とVSのコードポイント、コレクション名・登録識別子を表示する。同じIVSの複数登録を併記し、クリックでシーケンス全体を編集バッファへ追加する。表示用フォントと補完設定は他の異体字列と共通で、登録がない文字には欄を表示しない。狭い画面の文字情報ダイアログでも同じ内容と操作を提供する。データ取得に失敗した場合はエラーと再読み込みボタンを表示する。

操作ラベルなどのUIフォントはOSのUIフォントに続けて `Noto Sans JP`、`Noto Sans`、`sans-serif` を指定する。WindowsのFirefoxで日本語のフォールバック先を明示するため、`Noto Sans JP` を含める。端末にあるフォントを使い、外部からフォントを取得しない。

文字の既定書体は `serif`。保存済みのフォント指定を優先し、アプリの操作ラベルの書体は変更しない。表示設定のフォント名は自由入力のテキスト欄とし、「表示フォント（名前を入力）」と明示する。選択メニューと誤認しないよう候補一覧やドロップダウン矢印は付けない。「ブロックごとのフォント設定」も表示設定内へ置き、必要なときに展開して追加・変更・解除する。従来のブロック別設定は保持する。

フォントタブの解析用フォントは共通表示設定から分離する。左側にフォント一覧を置き、取得・ファイル読込・名前検索と縦並びの選択タブをまとめる。コレクションのフェイスも同じ一覧の独立したグループに表示する。上部には解析対象の名前と解除を固定する。幅700px以下では「フォント一覧」ボタンからダイアログを開き、適用後に閉じて解析対象へフォーカスを移す。タブ切替や非同期読込で共通の表示フォント設定を書き換えない。

フォントタブの中は横並びの3タブとし、選択中の作業領域だけを表示する。左右キーとHome/Endでタブを操作できる。小型画面でも対象フォントとタブ、編集バッファを固定し、各ビュー内部をスクロールする。

| タブ | 内容 |
| --- | --- |
| グリフマップ | 全収録文字／ブロック／全グリフ／単一文字の割当なし／SVS／IVSを選択欄で切替。共通の文字一覧で128件ずつ表示し、ページ送り・キー操作・挿入・TSV保存を共有。選択中の文字のグリフ情報を右側に表示。700px以下では下部に選択表示を置き、「グリフ情報」でダイアログを開く。上部は文字一覧ではコードポイント、グリフ一覧ではGlyph ID（10進数）を指定して該当ページへ移動する。 |
| サンプル | 選択フォントを反映した、編集バッファと同程度の入力欄。収録集計、OpenType設定、実グリフ付きの配置表、JSON保存。128行ずつ表示する。サンプル入力はタブ・フォント切替で保持する。 |
| フォント情報 | ファミリー、スタイル、バージョン、PostScript名、グリフ数、収録数、units per em、著作権。 |

グリフ情報はコードポイント・Glyph ID、解析対象から描いた輪郭、文字名、バッファへの追加・コピー、収録判定、グリフ名・横送り幅・輪郭の範囲・units per em、基本Unicode属性、SVG／PNG保存の順に並べる。一覧のクリック・矢印キー・ページ送り・コレクションのフェイス変更に追従する。未収録は.notdef、空白など輪郭を持たないグリフは「輪郭なし」と区別する。表示枠は縦横1.5em、ベースラインは上端から1.15emに固定する。フォント全体の巨大な輪郭に合わせた縮小を行わず、異なるunits per emでも1emの画面上の大きさを揃える。横方向は横送り幅の中央を表示枠の中央に合わせる。書体固有の字面の差は維持し、枠を越える大きな輪郭は切れる。詳細にはベースラインと原点の薄いガイドを付け、下部に原点から次の原点までの横送り幅を両端の目盛り付きで表示する。サンプル表とSVG／PNGも同じ座標枠を使い、出力にはガイドを含めない。文字一覧のPNGは表示用フォントが利用できない場合に無効にする。グリフ一覧のPNGは輪郭から作成するため、表示用フォントなしでも保存できる。狭い画面のダイアログはEscapeでも閉じ、開くボタンへフォーカスを戻す。ダイアログ内でPage Up/Downを押しても一覧は移動しない。

グリフ一覧は128件ごとに、.notdefを含む全Glyph IDを表示する。「単一文字の割当なし」はcmapの通常マッピングを持たないグリフを絞り込み、VS専用字形・合字・代替字形・未使用グリフも対象に含む。詳細では単一文字とVS列の対応を選べる。選択したVS列が同梱のUnicode異体字列データにある場合は「シーケンス名」を表示する。基底文字だけで照合せず、VSを含む列全体が一致した名前・説明を使う。対応文字列がある場合だけ追加・コピー・Enter／ダブルクリックでの挿入を有効にし、Unicode属性を別の文字から推測しない。合字・代替字形を生むOpenType置換規則の逆引きは行わない。

表示範囲の「Unicodeコードポイント」はUnicodeに対応する文字の一覧を表示する。「異体字列」グループでSVS・IVSを別々に選ぶ。標準化異体字列／IVD登録列と、フォントのcmap format 14の対応を照合し、128シーケンスずつ基底文字・VS順で表示する。基底文字とVSをセルに併記し、同一グリフへ対応する複数の列も独立して選択・挿入・コピー・TSV保存できる。通常グリフを使うデフォルトUVSも含める。選択列だけを詳細の対応文字列へ渡し、SVS名もその列に追従する。単一文字の収録だけではVS対応と判定せず、GSUBでのみ処理される列はこの範囲に含めない。絵文字表示列・未登録列はこれらの範囲に含めないが、既存の全グリフ表示から参照できる。読み込み中・失敗・該当なしを区別し、失敗時は再読み込みできる。

編集バッファの「カバレッジ」は「バッファをカバーするフォント」ダイアログを開き、クリック時の内容を対象に端末フォントを検索する。一つのフォントで全対象文字を収録する結果だけを名前・スタイル・PostScript名で一覧表示し、50件ずつのページ送りと名前の絞り込みに対応する。名前・スタイルの下には各フォントで対象テキストを描画したプレビューを置き、長文は高さを制限してスクロールできるようにする。表示できない場合は明示する。各項目の「解析」はダイアログを閉じ、該当フォントをフォントタブへ読み込み、解析対象の見出しへフォーカスを移す。TTC/OTCはフェイスごとに判定・描画・解析する。進捗・中止・再検索と読み込めないフォント数を示し、権限拒否・非対応環境・解析開始失敗を空の検索結果と区別する。閉じると検索を中止し、ボタンへフォーカスを戻す。検索・プレビューのみでは表示中のツール・解析フォントを変更しない。「解析」で移動した場合もサンプル・表示設定・バッファは保持する。対象は重複を除いた文字単位で、制御・表示調整用文字を除外する。対象がない場合と不正サロゲートを含む場合は端末フォントの取得を開始しない。異体字列・絵文字列・合字の表示対応は別であることを表示する。

フォントタブの「サンプル」は「編集バッファから読み込む」で現在の内容をコピーできる。以後の入力は独立する。表のGlyph IDはグリフマップの「全グリフ」へ移動し、該当ページとグリフを選択して情報を表示する。狭い画面ではグリフ情報ダイアログを開く。表内のコードポイントは、その行の出現位置をサンプル内で選択する。繰り返し文字・合字・VS列・右横書きの並び順を考慮し、補助面文字もUTF-16のペア全体を選択する。シェーピングで元文字との対応が失われた行は選択ボタンを無効にする。解析対象がなければフォント選択を案内する。単一コードポイントの収録を調べ、正規化は行わない。制御文字・書式文字・Default_Ignorable_Code_Pointと不正サロゲートは収録率の分母から外して別集計とする。異体字列や絵文字列の表示対応を判定するものではない。

収録文字の範囲とページはタブ切替で保持し、ファイル再読込・コレクションの解析対象変更・解除でリセットする。隠れた一覧はページキーを処理しない。文字検索の入力・検索結果は変更しない。文字コードからの文字表示とPNGはOSのフォールバックを含み、cmap判定と輪郭・SVGは解析対象に基づく。グリフ一覧のプレビューとPNGはGlyph IDから直接描画する。Glyph IDの隣に、置換後のグリフそのものをSVGで描く。未収録の行は背景色・左罫線と「未収録 (.notdef)」ラベルで示し、制御文字・無効なサロゲートと区別する。配置は先頭1,000コードポイントまでとし、切り詰めを明示する。収録数はサンプル全体を集計する。

端末フォントは列挙完了時点でPostScript名順に表示し、名前をワーカーで順次取得する。名前の取得中も検索・選択でき、表示名を更新しても並び順とフォーカスを維持する。クリックまたはEnter/Spaceで解析し、↑↓・Home/End・Page Up/Downはフォーカスだけを移動する。ファイル読込とコレクションのフェイス切替は、解析結果と表示用フォントが揃ってからまとめて適用する。読み込み中は直前の解析対象と一覧の名前・スタイル・PostScript名を維持する。解析状況は高さを確保した見出し上の行と対象行の枠・aria-busyで示し、一覧の情報を「解析中」で置き換えない。完了通知は表示しない。解除すると進行中の読み込みも無効にする。コレクションでは入力欄・文字一覧・PNGも選択フェイスを使う。表示できない形式でも解析結果は利用できるが、標準フォントで表示している旨を持続表示し、文字からのPNGを無効にする。Glyph IDからの輪郭表示・SVG／PNG保存は利用できる。

## 小型画面への適応

1024px以上では、条件カテゴリと追加欄を結果の左に366px幅（タブ140px）で並べ、結果の高さを確保する。枝番などの選択肢が切れないよう入力欄の幅も確保する。「条件追加を閉じる」で追加欄だけを畳める。条件チップは残るため、結果を広げても適用中の条件が分かる。

1000px以下では条件追加欄を結果の上へ移す。狭い画面の初期状態は折りたたみ、追加欄とチップはそれぞれ内部でスクロールできる。高さの少ないモバイルでは追加欄を小さくし、結果も見えるようにする。検索結果の列数は実際の表示幅に応じて16列／8列を切り替え、矢印キーの移動量も一致させる。

アプリ全体は `100dvh` の縦レイアウト。ヘッダーと編集欄を固定し、文字表・条件・プレビュー・各ツールの内側をスクロールさせる。文字サイズプレビューの局所 state / Context と、ページ間のセルDOM再利用を維持する。

## 機能を追加するときの置き場所

| 追加候補 | 置き場所・扱い |
| --- | --- |
| 数値、分解、改行、注記、複数値検索 | 文字検索の条件カテゴリとクエリ処理を拡張する |
| 未選定の漢字属性、声調、彝文字等の条件 | Unihan の条件は「漢字 (Unihan)」内へ追加する。別資料は必要に応じて条件カテゴリを追加し、資料固有の入力とチップ表示を一組で追加する |
| 標準化異体字列、IVS/IVD、その他の文字列資料 | 複数コードポイント用の共通プレビューを再利用する。`cps`・名前・資料固有属性を保持する。検索画面の名称・配置は対象資料の追加時に決める |
| フォントカバレッジ、Glyph mode、字形出力 | フォント画面、または対象に対応した表示設定・出力操作へ追加する |
| Unicode 履歴、版間差分、資料一覧 | Unicodeデータ画面へ追加する |
| 正規化、変換、保存形式 | 編集バッファの「変換・保存」へ追加する |

これは拡張先の設計であり、未実装データや検索条件を利用可能として表示しない。現在の検索対象に合わせ、タブ名は「絵文字検索」とする。

## 実装の境界

- `App`: トップレベルの画面、選択対象、設定、編集バッファとの接続。
- `SearchWorkspace` / `CharacterConditions` / `ConditionChips`: 検索入力、条件カテゴリ、適用済み条件、検索結果。
- `MapSearch`: マップ内検索の入力、一致一覧の再利用、現在位置からの循環移動。入力変更・手動移動・タブ切替後は古い要求で自動移動しない。
- `useCharacterSearch`: 文字検索のクエリ、結果、選択、ページ。古い要求の応答は結果を上書きしない。
- `useSearchWorker`: 両検索で共有する遅延起動の Worker と要求ID付き通信。Unicode データを検索画面ごとに重複ロードしない。
- `CharacterCollection`: 文字検索・ブックマークの結果表示、ページ送り、文字表への移動、一覧出力。
- `EmojiPanel`: 現在のシーケンス資料である絵文字の検索と一覧。`SequenceDetails` はコードポイント列・名前・属性を受け取ってプレビューする。
- `BlockNavigation` / `CodePointNavigation`: 文字マップ専用の移動。

条件を増やすときは、入力UI、クエリへの変換、チップの表示・解除、Workerの処理、複合条件と遅延応答のテストを一単位として追加する。トップレベルのタブや共通ツールバーへ条件入力を直接追加しない。


## フォント名と表示言語

フォント名・ファミリー名・スタイル名は共通ロケールのUI言語を優先し、なければ英語を表示する。日本語UIでは日本語名を持つフォントは日本語で、Arial Italicのように日本語名がないフォントは英語で表示する。両方ない場合や名前を読めない場合もPostScript名で識別できるようにし、第三言語を勝手に選ばない。検索、カバレッジ一覧の並び順、端末フォントの候補、解析対象の見出しとコレクション内の候補、Family/Styleに適用する。端末フォント一覧は名前の更新で行が移動しないようPostScript名順を保つ。端末フォントの名前取得は進捗を表示する。

現在のUI言語は日本語。共通ロケールの基盤は導入するが、言語設定画面とUI文言の翻訳は後続で対応する。設計は [intl.md](intl.md) を参照。
